## 1. Резюме проекта

**Проблема:** Покупатель, который облицовывает крыльцо, лестницу или террасу, не находит в интернете специализированного поставщика именно клинкерных ступеней и крупноформатного керамогранита для улицы. Запросы «клинкерные ступени для крыльца», «ступени для лестницы на улице», «керамогранит для террасы 20 мм», «плитка для дорожек на опорах» ведут на общие плиточные каталоги без расчёта элементов, без понимания систем (проступь / подступёнок / угол / плинтус) и без цен.

**Решение:** Отдельный лендинг + подстраницы (категории, бренды и решения по применению). Ассортимент структурирован в **три продуктовые категории**:
1. **Террасный клинкер** — клинкерная плитка и ступени для крылец, уличных лестниц и террас (проступь/подступёнок/угол/капинос/базовая плитка), укладка на клей.
2. **Террасные пластины** — крупноформатный керамогранит 20 мм для террас, входных площадок и дорожек, в т.ч. укладка на регулируемые опоры (пьедесталы) и на клей.
3. **Террасные пластины под дерево** — крупноформатный керамогранит с текстурой дерева (декинг-эффект) для террас и зон отдыха.

Главная конвертирует рекламный трафик в заявки, подстраницы закрывают SEO/GEO-спрос по брендам, категориям и сценариям применения. Ключевой инструмент — **калькулятор с двумя режимами** (лестница/крыльцо и терраса/площадка), который считает не «квадраты вообще», а штуки плитки/ступеней по реальному размеру (30×30, 30×60), опоры по таблице производителя и сопутствующие материалы с ценой по городу.

**Цель:** Конверсия в заявку ≥ 3% с рекламного трафика; органический и AI-трафик (цитируемость в ChatGPT/Perplexity/Яндекс Нейро) через 4–6 месяцев после запуска.

**Ключевой дифференциатор:** Калькулятор лестниц с добавлением произвольного числа маршей и поэлементным расчётом ступеней в штуках + калькулятор террасы с выбором способа монтажа (клей / регулируемые опоры) и точным расходом опор по таблице HILST LIFT. Сопутствующие материалы (клей, грунтовка, гидроизоляция, затирка) с ценой по городу. Открытые цены, квиз подбора, 3D-визуализация, карта объектов — функционала такого уровня нет у конкурентов в нише уличного клинкера и террасного керамогранита.

## 2. Целевая аудитория

| Сегмент | Боль | Что хочет от сайта |
|---|---|---|
| Частный домовладелец (загородный дом, дача) | Не знает, чем облицевать крыльцо/лестницу/террасу, боится, что зимой треснет и будет скользко | Понять, что подойдёт для улицы (морозостойкость, R-противоскольжение), увидеть цену, рассчитать комплект, посмотреть как будет выглядеть |
| Ландшафтный дизайнер / архитектор | Нужны конкретные форматы, фактуры, толщина 20 мм, системы укладки на опоры для террас и дорожек | Каталог форматов и цветов, технические параметры, образцы, расчёт, прямая связь без посредников |
| Прораб / монтажная бригада | Нужно посчитать комплект ступеней (сколько проступей, углов, подступёнков) и не ошибиться | Поэлементный расчёт, наличие, цена за элемент, расход клея/опор, документы |
| Застройщик / благоустройство (B2B) | Входные группы, террасы, площадки на объёме — нужна цена и логистика | Оптовые цены, расчёт по площади, доставка, гарантии, сертификаты |

## 4. Трафик и SEO

### Яндекс.Директ
- Рекламные группы под два смысловых кластера: **ступени** (крыльцо, лестница) и **террасы/ландшафт** (керамогранит 20 мм, дорожки, опоры).
- Отдельные группы на страницы решений (выше конверсия, чем общий лендинг).
- UTM-метки (source, medium, campaign, content, term) сквозь передаются в Битрикс24.
- Конверсионные цели: отправка формы, клик по телефону, завершение квиза, отправка расчёта из калькулятора, заказ образца.

### Общие правила дизайна
- **Фотостиль:** реальные объекты — крыльцо, лестница, терраса, дорожки. Крупные планы фактуры и капиноса ступени, ракурс «носик ступени». Кадры «до/после». Никакого стока.
- **Анимации:** fade+slide карточек при скролле; живые счётчики; hover-поднятие тени на карточках; параллакс на крупных фото. **Reveal-эффекты и параллакс — нативными scroll-driven animations (CSS), не JS-скроллом** (дешевле, плавнее, доступнее).
- **Переходы между страницами:** **View Transitions API** (кросс-документные при SSR) для плавной навигации сценовая карточка → решение → карточка товара; обязательный graceful-fallback (мгновенная навигация без перехода) для браузеров без поддержки.
- **Motion-доступность:** все анимации и переходы — под `@media (prefers-reduced-motion: no-preference)`; для пользователей с reduced-motion эффекты отключаются.
- **Логотип Hit Ceramics:** полноцвет на светлом фоне (шапка), белый — на тёмном (футер).
- **Адаптив:** сначала мобильный (основной трафик с Директа — мобильный).

## 8. Карточка товара

Карточка универсальна, но **тип товара** определяет состав параметров: `step_system` (ступени, поэлементно) или `slab` (пластина/формат, по м²).

### 8.1 Шапка карточки
```
[Хлебные крошки: Главная → Ступени → Paradyz → Taurus Brown ступень]

[Галерея 4–8 фото]   |  Paradyz
(лайтбокс)           |  Taurus Brown — клинкерная ступень с капиносом
                     |  Артикул: {SKU}
                     |  Тип: Клинкерные ступени  |  Применение: крыльцо, лестница (улица)
                     |
                     |  [Элемент: Ступень фронтальная ▼]  ← select, меняет цену/размер/вес
                     |     (фронтальная / угловая левая / угловая правая / подступёнок / базовая плитка / плинтус)
                     |
                     |  Цена за элемент:  {PRICE} ₽
                     |  Цена за пог.м:    {PRICE_LM} ₽   (для линейных элементов)
                     |  Цена за м²:       {PRICE_M2} ₽   (для базовой плитки / пластин)
                     |
                     |  [Заказать]  [Заказать образец]  [Сравнить]
                     |  [Рассчитать комплект →]   (открывает калькулятор с предзаполнением)
```

Для товара типа `slab` селект «Элемент» отсутствует — вместо него селект «Формат» (см. правило формата ниже), цена за м²/шт.

**Промо-механика цены (по образцу Exagres / lexa-klinker).** Если у артикула задана акция:
- **Бейдж скидки** над галереей и на карточке витрины (например «−15 %» или «Акция»).
- **Старая цена зачёркнута**, рядом — новая выделенная: `1 250 ₽` → **`1 060 ₽`**.
- Все цены с пометкой **«за шт. с НДС»** (или «за м² с НДС» / «за пог.м с НДС» — по типу элемента), чтобы исключить вопросы о НДС.
- **Таймер акции** (обратный отсчёт до даты окончания), если у промо задан дедлайн; по истечении цена и бейдж автоматически возвращаются к базовым.
Поля промо (`old_price`, `discount_percent`, `promo_label`, `promo_ends_at`) — в артикуле CMS; менеджер включает/выключает акцию без участия разработчика (см. §13).

## 9. Калькулятор

Калькулятор имеет **два режима** (табы). Переключение режима меняет поля ввода и формулы. Результат **реактивный** — пересчитывается мгновенно при любом изменении, без кнопки. Цены **редактируемые** (подставляются из CMS, пользователь может изменить).

```
[ Режим A: Лестница / крыльцо (ступени) ]   [ Режим B: Терраса / площадка (пластины) ]

Глобальный переключатель города:   ( • Москва )  ( ○ Санкт-Петербург )
```

### 9.0 Глобальный переключатель города (Москва / Санкт-Петербург)

Над обоими режимами — тумблер города (паттерн взят из калькулятора Hit Ceramics, вкладка «Террасный клинкер»). Город определяет, по какой колонке цен считаются **сопутствующие материалы** (клей, грунтовка, гидроизоляция, затирка) — см. справочник 9.3. По умолчанию — Москва. Цена самой плитки/ступеней — из CMS (от города не зависит, редактируется вручную).

### 9.1 Режим A — Лестница / крыльцо (поэлементный расчёт ступеней)

#### 9.1.1 Лестничные марши (динамические строки «+/−»)

Расчёт ведётся по **маршам**. По умолчанию один марш; кнопка **«+ Добавить марш»** добавляет строку, кнопка **«−»** (или 🗑) у строки удаляет её (если маршей > 1). Параметры каждого марша независимы и суммируются.

| Поле строки марша | Тип | Описание |
|---|---|---|
| Название (опц.) | text | «Крыльцо», «Лестница к террасе» |
| Кол-во ступеней, N | number | Число ступеней в марше |
| Ширина марша, W (м) | number | Ширина ступени по фронту |
| Глубина проступи, d (м) | number | Глубина ступени (для базовой плитки и наклона) |
| Высота подступёнка, h (м) | number | Высота вертикали ступени |
| Внешних углов марша | select | 0 / 1 / 2 |
| «−» Удалить марш | button | если маршей > 1 |

Общие переключатели (на весь расчёт):

| Поле | Тип | Описание |
|---|---|---|
| Облицовывать подступёнки? | toggle | Да/Нет |
| Боковины (плинтус)? | toggle | Да/Нет — облицовка наклонной боковины марша |
| Верхняя площадка (крыльцо): Д×Ш (м) | number×number | Опц. — базовая плитка площадки |

#### 9.1.2 Выбор системы, размера плитки и цен

| Поле | Тип | Описание |
|---|---|---|
| Бренд / Коллекция / Цвет | select | Из каталога CMS (Paradyz, Exagres, Маркастрой, Stroeher, Westerwälder Klinker, Interbau) |
| Размер базовой плитки | radio | **30×30** (11.11 шт/м²) / **30×60** (5.56 шт/м²) |
| Длина фронтального элемента, Lф (м) | авто | Из артикула (напр. 1.2) |
| Длина подступёнка, Lп (м) | авто | Из артикула |
| Длина плинтуса, Lпл (м) | авто | Из артикула |
| Ширина угловой ступени, Wугл (м) | авто | Из артикула |
| Цена фронтальной (₽/шт) | number | Редактируемое |
| Цена угловой L/R (₽/шт) | number | Редактируемое |
| Цена подступёнка (₽/шт) | number | Редактируемое |
| Цена базовой плитки (₽/шт) | number | Редактируемое |
| Цена плинтуса (₽/шт) | number | Редактируемое |

> **Правило элементов:** список доступных элементов и их длины берутся строго из массива `elements[]` артикула (раздел 17). Если у артикула нет, например, плинтуса — соответствующая опция скрыта/заблокирована. Калькулятор не предлагает элементы, которых нет у товара.

#### 9.1.3 Формулы (запас на подрез k = 5%, т.е. ×1.05; суммируются по всем маршам)

Для каждого марша *i*:

| Величина | Формула |
|---|---|
| Погонаж проступи (м) | `Pпро_i = N_i × W_i` |
| Угловые элементы (шт) | `Aугл_i = N_i × внешних_углов_i` |
| Фронтальные элементы (шт) | `Fфр_i = ceil( (Pпро_i − Aугл_i × Wугл) / Lф × 1.05 )` |
| Подступёнки (шт), если включены | `Fпод_i = ceil( Pпро_i / Lп × 1.05 )` |
| Длина наклона марша (м) | `Lнакл_i = N_i × √(d_i² + h_i²)` |
| Плинтус (шт), если боковины | `Fпл_i = ceil( (2 × Lнакл_i) / Lпл × 1.05 )` |

Итоги по всем маршам и площадке:

| Величина | Формула |
|---|---|
| Угловых / фронтальных / подступёнков / плинтусов | `Σ по маршам` каждого типа |
| Базовая плитка площадки (шт) | `Fбаз = ceil( (Дпл × Шпл) × шт_м²(размер) × 1.05 )`, где шт_м² = 11.11 (30×30) или 5.56 (30×60) |
| Поддонов | `ceil( кол-во_по_типу / шт_поддон )` суммарно |
| **Стоимость элементов** | `Σ ( кол-во_элемента × цена_элемента )` |
| Сопутствующие материалы | по площади облицовки (площадка + проступи + подступёнки), см. 9.3 |
| Вес поставки (т) | `Σ( кол-во × вес_шт ) / 1000` |

#### 9.1.4 Пример расчёта (Режим A)

Два марша. Марш 1 (крыльцо): N = 5, W = 1.5 м, d = 0.30 м, h = 0.15 м, 2 угла. Марш 2 (короткий): N = 3, W = 1.2 м, d = 0.30, h = 0.15, 2 угла. Подступёнки да, боковины да, площадка 1.5 × 1.2 м, размер базовой 30×30 (11.11 шт/м²). Артикул: Lф = 1.2 м, Lп = 1.2 м, Lпл = 0.3 м, Wугл = 0.32 м.

Марш 1:
- `Pпро = 5 × 1.5 = 7.5 м`; угловых `5 × 2 = 10`
- Фронтальные: `ceil((7.5 − 10×0.32)/1.2 × 1.05) = ceil(3.76) = 4 шт`
- Подступёнки: `ceil(7.5/1.2 × 1.05) = ceil(6.56) = 7 шт`
- Наклон: `5 × √(0.09+0.0225) = 5 × 0.335 = 1.68 м`; плинтус `ceil(2×1.68/0.3 × 1.05) = 12 шт`

Марш 2:
- `Pпро = 3 × 1.2 = 3.6 м`; угловых `3 × 2 = 6`
- Фронтальные: `ceil((3.6 − 6×0.32)/1.2 × 1.05) = ceil((3.6−1.92)/1.2 ×1.05) = ceil(1.47) = 2 шт`
- Подступёнки: `ceil(3.6/1.2 × 1.05) = ceil(3.15) = 4 шт`
- Наклон: `3 × 0.335 = 1.01 м`; плинтус `ceil(2×1.01/0.3 × 1.05) = ceil(7.07) = 8 шт`

Площадка: `ceil(1.5×1.2 × 11.11 × 1.05) = ceil(21.0) = 21 шт`.

**Итого:** угловых 16, фронтальных 6, подступёнков 11, плинтусов 20, базовая 21 шт. Стоимость = сумма по ценам элементов; сопутствующие материалы — по площади облицовки в выбранном городе (9.3); вес = сумма весов / 1000.

#### 9.2.6 Формулы (Режим B)

| Величина | Формула |
|---|---|
| Площадь нетто (м²) | `Sнетто = Σ(Дi×Шi) − Σ вычеты` |
| Площадь с запасом (м²) | `Sзап = Sнетто × (1 + запас)` |
| Плит (шт) | `ceil( Sзап / Sплиты )`, где `Sплиты` из формата |
| Поддонов | `ceil( плит / шт_поддон )` |
| **Стоимость плитки** | `плит × цена_шт` (или `Sзап × цена_м²`) |
| Опоры (шт), если на опоры | `ceil( Sнетто × опор_м²(формат, площадь) )` по таблице 9.2.4 → стоимость |
| Сопутствующие материалы, если на клей | по таблице 9.3 (расход × Sнетто, по городу) → мешки/канистры → стоимость |
| **Итого материалы** | `стоим_плитки + стоим_опор_или_материалов` |
| Вес поставки (т) | `(плит × вес_плиты + мешки × фасовка) / 1000` |

#### 9.2.7 Пример расчёта (Режим B — на опоры)

Терраса 5 × 4 м (20 м²), формат 600×600 (Sплиты = 0.36 м², вес ~16 кг, шт/поддон из CMS), на регулируемые опоры HILST, прямая раскладка.

- `Sнетто = 20 м²`; `Sзап = 20 × 1.05 = 21 м²`
- Плит: `ceil(21 / 0.36) = ceil(58.3) = 59 шт`
- Опоры: площадь 20 м² → колонка «20 м²», формат 600×600 → **6.80 опор/м²**; `ceil(20 × 6.80) = 136 опор`
- Стоимость = 59 × цена_плиты + 136 × цена_опоры.

#### 9.2.8 Пример расчёта (Режим B — на клей, город Москва)

Терраса 6 × 4 м, вычет круглой клумбы Ø1.0 м, формат 600×1200 (Sплиты = 0.72 м², вес 32 кг, шт/поддон 40), на клей, прямая раскладка, сопутствующие материалы вкл., город **Москва**.

- `Sнетто = 24 − π×0.5² = 24 − 0.79 = 23.21 м²`; `Sзап = 23.21 × 1.05 = 24.37 м²`
- Плит: `ceil(24.37 / 0.72) = ceil(33.8) = 34 шт`; поддонов `ceil(34/40) = 1`
- Клей Flex FKC (5 кг/м², меш. 25 кг): `23.21 × 5 = 116.1 кг → ceil(116.1/25) = 5 мешков × 2261.83 = 11 309 ₽`
- Грунтовка UG (0.4 кг/м², кан. 10 кг): `23.21 × 0.4 = 9.28 кг → ceil(9.28/10) = 1 × 1322.84 = 1 323 ₽`
- Гидроизоляция MDS (4 кг/м², меш. 25 кг): `23.21 × 4 = 92.8 кг → ceil(92.8/25) = 4 × 1741.04 = 6 964 ₽`
- Затирка FUG FBR (0.45 кг/м², меш. 25 кг): `23.21 × 0.45 = 10.4 кг → ceil(10.4/25) = 1 × 1393.25 = 1 393 ₽`
- Сопутствующие материалы итого ≈ **20 989 ₽** (Москва); для СПб — по второй колонке цен (9.3).
- Стоимость = 34 × цена_плиты + 20 989 ₽.

| Параметр | Требование |

| **Отзывчивость (INP)** | **INP < 200 мс**, особенно для калькулятора (реактивный пересчёт на каждый ввод, Режим A с маршами — самый тяжёлый). Тяжёлые пересчёты дробить, чтобы не блокировать отклик. Поле собирать через библиотеку `web-vitals` (onINP с атрибуцией) → бикон в аналитику. |

| **Отложенный рендер длинных списков** | `content-visibility: auto` + `contain-intrinsic-size` на офскрин-карточках сеток каталога и страниц решений/брендов — ускоряет первый рендер при больших списках. |
| Адаптивность | 320 / 768 / 1024 / 1280 / 1920 px |
| Кроссбраузерность | Chrome, Firefox, Safari, Edge (последние 2 версии) |
| HTTPS | Обязательно, валидный сертификат, HSTS |
| Доступность | Alt на всех фото, контраст ≥ 4.5:1, tab-навигация. **Состояния ошибок форм — не только цветом**: иконка/текст + рамка; `aria-invalid`/`aria-errormessage` синхронны с визуальным `:user-invalid`, чтобы скринридер получал ошибку после взаимодействия (см. §9/§10). |
| **Валидация форм** | Нативная HTML5 (`type`, `pattern`, `required`) + псевдоклассы `:user-invalid`/`:user-valid`: ошибка показывается **только после ухода с поля или сабмита**, не во время ввода; зелёный success при корректном значении. На всех полях — `autocomplete` (`name`/`tel`/`email`) для автозаполнения на мобильных. JS-fallback для старых браузеров (отслеживание «dirty» через WeakMap). |
| **Анимации/переходы** | Все эффекты под `@media (prefers-reduced-motion: no-preference)`. Параллакс и reveal-эффекты — нативными **scroll-driven animations** (CSS), а не JS-скроллом. ### A.4 Definition of «10 из 10»
Сайт считается доведённым до 10/10, когда: все маршруты §3 существуют и отдают уникальный SSR-контент; PageSpeed Mobile ≥ 90, LCP < 2.5 c, INP < 200 мс, CLS < 0.1; Lighthouse SEO = 100, Accessibility ≥ 95; присутствует полный JSON-LD и проходит валидацию Rich Results; sitemap/robots/llms.txt отданы; мобильное меню и формы доступны с клавиатуры; калькулятор и все формы доезжают до Битрикс24 с тегами; ошибки A.2 (E1–E10) закрыты.

### B.2 Правовой и рекламный комплаенс РФ (блокеры запуска)

> Лендинг на платном трафике Директа без этого слоя юридически дефектен на каждой форме; суммарный риск штрафов (152-ФЗ + 38-ФЗ + ЗоЗПП + РКН) делает запуск недопустимым.

- **152-ФЗ — явное согласие на обработку ПД.** Заменить пассивную фразу «нажимая, вы соглашаетесь» (в сборке `LeadModal.tsx:126`) на **отдельный непредотмеченный чекбокс** во всех формах (§6 Блоки 21/23, §9.4, §10, §11.1, §6 Блок 15); submit заблокирован до отметки; ссылка на Политику в тексте у чекбокса; **второй отдельный чекбокс** для маркетинга/рассылок (не смешивать цели). *Штраф юрлицу 300–700 тыс. ₽, повтор до 1,5 млн.*
- **Cookie-баннер (cookie = ПД с 30.05.2025).** Баннер при первом визите (принять / отклонить / настроить категории: технические / аналитика / реклама); Метрика (вебвизор, карта кликов), коллтрекинг и чат запускаются **только после согласия** (Consent Mode / условие в GTM); таблица cookie в Политике (тип/цель/срок); хранение на серверах РФ. (Дополняет §15, §16, §6 Блок 22.)
- **Маркировка рекламы (38-ФЗ, ОРД/ЕРИР).** Новый подраздел §4: для всех креативов Директа — токен `erid` через ОРД Яндекса, пометка «Реклама» + наименование/ИНН ООО «ЗЕ ВАН» (7806568970); любые баннеры акций/кросс-промо других ресурсов группы на лендинге — помечать; регламент ежемесячной сверки ОРД→ЕРИР. *РКН в 2026 ищет разрывы цепочки автоматически.*
- **Торговое право.** Дисклеймер «информация на сайте не является публичной офертой» рядом с ценами (цены скачут 3×/нед — иначе обязывает продать по опубликованной); страница **«Оплата, доставка, возврат и обмен»** по ЗоЗПП и Правилам дистанционной продажи; полные данные продавца (ООО «ЗЕ ВАН», ОГРН/ИНН/адрес/режим) в футере и на «Контактах»; актуальность сертификатов соответствия как обязательство (не только «ссылка на PDF» в §8.2).
- **Доступность по ГОСТ Р 52872-2019.** В §15 указать ГОСТ как нормативную базу РФ (WCAG 2.2 AA — способ её выполнить); решить вопрос «версия для слабовидящих vs универсальный дизайн»; опубликовать **заявление о доступности** (важно для B2B-тендеров застройщиков/благоустройства, §2).

### B.3 SEO для Яндекса/РФ

- **Яндекс-инфраструктура (новый подраздел §4):** верификация в Вебмастере + отправка sitemap + IndexNow/«Переобход»; **привязка «Регион сайта» = Москва и Санкт-Петербург**; карточки **Яндекс.Бизнес** на 2 склада (Подольск; Тосненский р-н) и 2 шоу-рума (Калужская; Новочеркасская) с единым NAP; синхронизация NAP на 2ГИС/Zoon. *Региональность в Яндексе задаётся Вебмастером+Бизнесом, не разметкой — без этого гео-зависимые «купить»-запросы не ранжируются.*
- **Индексация каталога и фильтров (новый подраздел §4/§7.1):** список индексируемых SEO-фильтров на **path-URL** (напр. `/producers/paradyz/dlya-kryltsa/`, `/terrasnyy-klinker/seryy/`) с уникальными title/H1/SEO-текстом и self-canonical; все прочие комбинации/сортировки/GET-параметры → `noindex,follow` + canonical на категорию; директива **Clean-param** в robots для Яндекса; правило пагинации (`?page=N` обходится, canonical-на-себя). Генерация таких страниц — в CMS (§13) и sitemap.
- **Коммерческие факторы Яндекса (новый подраздел §4, ~60–70% веса коммерческой выдачи):** реальная цена на каждой активной карточке (запрет публиковать `price_rub=0` → политика статусов цены, см. B.9); индексируемый статус наличия; страница «Оплата/доставка/возврат» с **зонами и ориентир-ценами** (а не только «индивидуально» — это коммерческий минус); гарантии/сертификаты текстом.
- **Расширенная микроразметка:** `Product` → `Offer{price, priceCurrency:'RUB', availability, priceValidUntil}`; `AggregateRating`/`Review` — **только при реальных отзывах** (иначе риск санкций за фиктивную разметку → добавить блок отзывов на карточку); `ItemList`/`CollectionPage` на категории/бренды/решения; `Service`/`OfferCatalog` на §10. Проверка в **Валидаторе микроразметки Яндекса**, не только Google Rich Results.
- **Мультирегиональность Мск/СПб (§3/§4):** гео-страницы `/msk/` и `/spb/` (или региональные посадочные ключевых категорий) с гео-вхождениями в title/H1 («…в Москве» / «…в Санкт-Петербурге»), блоком склад/шоу-рум/самовывоз города, ценами калькулятора по городу; каждый регион привязан в Вебмастере. (Согласовать с B.10.)
- **Семантическое ядро (заменить мини-таблицу §4):** собрать ядро из **Yandex Wordstat** (скилл `yandex-wordstat`), кластеризовать по интенту и частотности; карта «1 интент = 1 URL» с явным разнесением каннибализирующих ключей (категория = ассортимент/выбор, решение = сценарий/как выбрать — сейчас «клинкерные ступени для крыльца» висит на обеих); список LSI/сущностей (F100, R11, водопоглощение, капинос, пог.м) + коммерческие модификаторы (цена/купить/в наличии/с доставкой) на страницу. Зафиксировать как deliverable `seo_base_*`.
- **Индексация/свежесть:** Турбо-страницы Яндекса **не используем** (технология прекращена в 2025) — ставка на быстрый SSR; добавить IndexNow на публикацию карточек/статей, корректные `Last-Modified`/`ETag`, `lastmod` в sitemap, еженедельный контроль «Страниц в поиске»/«Диагностики».

### B.4 GEO / цитируемость в AI

- **Связка «GEO = топ-20 органики Яндекса» (новый подраздел §4 + Прил. A§6):** Яндекс Нейро/Алиса формируют ответ **только из сайтов топ-20–30** обычной выдачи — для главного движка РФ GEO невозможен без классического SEO-ранга. Приоритизировать GEO-страницы (решения/бренды) для вывода в топ-20; в §18 — KPI «топ-20 Яндекса по N приоритетным запросам через 4–6 мес» как ведущий индикатор GEO. YandexGPT/GigaChat — отдельные пайплайны от ChatGPT/Perplexity.
- **Офсайт-сигналы (новый подраздел §4):** упоминания бренда коррелируют с AI-видимостью ×3 сильнее ссылок; 90% AI-цитат — из earned/owned-медиа. Программа: экспертные материалы/кейсы на forumhouse, mastergrad, Дзен, vc.ru, отраслевых каталогах с упоминанием бренда; попадание в чужие сравнительные подборки «лучшие клинкерные ступени / керамогранит 20 мм для улицы»; в §18 — метрика share of voice в AI-ответах (мониторинг llmrefs/profound).
- **Внешние отзывы/рейтинги (§4/§7):** заполнить профили Яндекс.Бизнес обоих городов, программа сбора отзывов (Яндекс.Карты, профильные площадки) с целевым рейтингом ≥4.7; в JSON-LD использовать только подтверждаемый внешними источниками `aggregateRating`. *AI считает онсайт-отзывы ангажированными — внешние весомее.*
- **Свежесть контента (§4 + Прил. A§6):** `dateModified` в Article/Product/страницах решений + видимая строка «Обновлено: {дата}»; `sitemap.ts` отдаёт реальный `lastmod` из CMS; регламент ревизии GEO-страниц ≤90 дней; **только реальные** изменения меняют дату. *Половина AI-цитат — контент моложе 13 недель; цены и так меняются 3×/нед (§13.2) — капитализировать это как freshness-сигнал.*
- **Авторство/экспертность (§4/§11.8):** сущность `Person` (1–2 эксперта компании — технолог/инженер) с квалификацией; `author`+`reviewedBy` в Article/HowTo; видимый байлайн на статьях-инструкциях; блок «Проверено технологом Hit Ceramics» на решениях. *Author-schema даёт ~×3 цитируемость.*
- **Переоценка `llms.txt` (Прил. A§6):** понизить в приоритете и пометить «не влияет на цитируемость в проде AI-поиска 2026» (оставить как дешёвую гигиену + опц. `llms-full.txt` для B2A/MCP-агентов); вверх вынести реальные драйверы (топ-20, офсайт, freshness, авторство). Главный канал для AI-ботов — обычный краулинг HTML.
- **Редстандарт «cite-bait» (§4 + бриф контент-менеджеру):** первые 2–3 предложения — прямой самодостаточный ответ с числом; ≥1 проверяемый факт/число со ссылкой (ГОСТ/EN/тех.лист) каждые 150–200 слов; каждый абзац — island-test; ≥1 сравнительная таблица на ключевых страницах; запрет метафор (Алиса хуже работает с эмоциональным текстом).
- **Бренд как сущность (§4):** расширить `sameAs` за пределы соцсетей (Яндекс.Бизнес, отраслевые каталоги, маркетплейсы); запись в Wikidata с единым описанием; связать `Organization` с brand-сущностями производителей (`about`/`mentions`).

### B.10 Разрешённые архитектурные противоречия (между измерениями)

1. **Наличие/цена/кэш.** Нельзя одновременно агрессивно кэшировать (PPR), размечать `availability` как факт и не иметь real-time источника. **Решение:** наличие/цена — динамическая Suspense-граница с коротким `cacheLife`, привязанная к 1С (B.9); статичны только описания/характеристики.
2. **Пустая цена vs импорт.** Жёсткий запрет `price=0` (требование коммерческих факторов) конфликтует с импортом партиями. **Решение:** политика статусов цены (актуальна / под заказ / архив), а не бинарный запрет нуля; «под заказ» — легитимный индексируемый статус с ценой «по факту поставки».
3. **GEO-авторство vs анонимность/отзывы.** Author-schema (×3 цитируемость) и запрет фиктивного `AggregateRating` оба требуют **реальных орг-действий**: назначить эксперта-технолога и собрать реальные внешние отзывы — это орг-задача, а не разметка.
4. **Мультирегион vs город-калькулятора vs кэш.** Гео-страницы (SEO), runtime-переключатель города §9.0 и статический PPR не согласованы. **Решение (рекомендация):** **одна** модель — URL-сегменты `/msk/` и `/spb/` для гео-посадочных с привязкой регионов в Вебмастере; тот же выбор города передаётся в калькулятор и в кэш-ключ. Не дублировать контент бесцельно (риск каннибализации).
5. **Двойной `6.71` в HILST** — см. B.11.
